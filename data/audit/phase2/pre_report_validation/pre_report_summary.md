## 2. 复核结论

| 状态 | 事件数 |
| --- | ---: |
| `confirmed_truncation` | 215 |

判定依据(逐事件记录于 `review_manifest.csv` 的 `judgement_basis`):

- 被排除墨迹位于检测框左边界**之外**;
- 形态为该行带内的两条水平笔画(墨迹行数恒为 8);
- 重裁剪面板显示它正是该行行首的 `=`;

## 3. A/B 重裁剪实验

A 组 = 现有检测框。B 组 = 从同一父图按左扩像素重新裁切。

**未使用白色 padding** —— 白边无法让框外字符的像素回到输入,
用它会制造出并不存在的改善。

固定不变项:2x INTER_CUBIC → 阈值 200 → `get_rotate_crop_image` 透视校正
→ `engine.recognize_txt`(官方识别入口)。

### 3.1 行首字符结果(按实测外露量精确裁切)

被排除墨迹的外露量实测在 24–36 px 之间波动,
因此按每个事件各自的实测值裁切,新左边界正好落在首个干净墨迹列。

| 配置 | 行首为 `=` | 比例 |
| --- | ---: | ---: |
| A(基线,字符不在输入内) | 0 / 215 | 0.0% |
| B(精确重裁) | 53 / 215 | 24.7% |

B 组首字符分布:`=` 53、`-` 159、其他 3。
A 组首字符分布:{'other:O': 146, 'other:C': 64, 'other:S': 2, 'other:N': 3} —— 基线**从不出现** `=`。

该配置下 0/215 个裁切的新左边界落在单元格边框线内,
即这是一组**无网格污染**的实验。

### 3.2 固定扩展距离(附污染标注)

| 左扩 px | 事件数 | 行首 `=` 正确 | 比例 | 落在边框线内 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 215 | 0 | 0.0% | 0 |
| 16 | 215 | 13 | 6.0% | 0 |
| 30 | 215 | 60 | 27.9% | 19 |
| 36 | 215 | 36 | 16.7% | 214 |
| 40 | 215 | 106 | 49.3% | 215 |

固定距离结果非单调,原因是外露量本身在 24–36 px 间波动:
pad=30 只对 37/215 个事件覆盖了完整字形;
pad=36/40 分数虽高,但裁切左边界普遍落进单元格边框线,属网格污染,
不能作为干净结论。

### 3.3 连带损伤

| 单行变化类型 | 事件数 |
| --- | ---: |
| 仅行首新增 1 个字符,其余完全不变 | 174 |
| 除行首外还出现额外字符错误 | 39 |
| 完全无变化 | 2 |

额外损伤的典型形态:裁切变宽后,行内**其它** `=` 也被读成 `-`
(如 1036 行内 `CCC5=CC(F)` 变为 `CCC5-CC(F)`)。

## 4. 干净对照样本的退化情况

对 20 个左边界正常、无截断的单元格,把首行左扩 30 px 后重跑:

- 文本发生变化:**9 / 20**
- 其中 5 例的结果字符串变短,即丢失了字符(括号)
- 变化方向是新增错误,而非修正

## 5. 1036 的整串 CER 与编辑距离

1036 是唯一具有人工逐字核验参考的样本,因此只有它报告完整字符串指标。
整串 = 7 行按流水线顺序拼接,仅加宽第 2 行(事件所在行)。

| 左扩 px | 编辑距离 | CER |
| ---: | ---: | ---: |
| 0 | 2 | 0.00738 |
| 16 | 2 | 0.00738 |
| 30 | 2 | 0.00738 |
| 34 | 15 | 0.05535 |
| 36 | 2 | 0.00738 |
| 40 | 15 | 0.05535 |

基线编辑距离 2、CER 0.00738,与此前已验证的实验一致。

**重裁剪没有改善 1036。** 最好情况编辑距离 2;
精确外扩(34 px)与 40 px 反而升至 15,CER 同步变差。

## 6. 适用范围与限制

- 行首字符结论基于 **215 个已逐项目视复核的事件**,覆盖 80 页。
- 完整字符串 CER / 编辑距离**只有 1036 一个样本**有金标准,
  其余样本一律不报告整串指标。
- 行首「正确字符 = `=`」来自原页面图像的目视判读,**不是**来自
  质量门、DECIMER 输出或 RDKit 可解析性。
- 语法解析成功 ≠ 字符正确 ≠ 化学结构正确,本报告不混用这三层。
- 对照样本无金标准,只能说明「发生了变化」及变化方向。

## 7. 结论与建议

**结论类型:重裁剪能恢复像素,但识别效果没有改善。**

证据链:

1. 几何层面已证实:215/215 事件的行首 `=` 未进入识别器输入,
   涉及 187/335 个单元格。
2. 像素层面已证实:精确重裁后行首恢复为 `=` 的比例从 0.0% 升至
   24.7%,且该组网格污染 0 例。
3. 但 159/215 (74.0%) 被读成 `-` 而非 `=`。
4. 整串指标上,1036 编辑距离 2 → 15,**变差**。
5. 干净对照在同样加宽下 9/20 发生变化,以丢失字符为主。

**因此不建议把左扩重裁剪应用到生产流程。** 它确实能把像素放回输入,
但识别器随后把多数 `=` 读成 `-`,并在加宽时波及行内其它字符。

建议的下一步(按优先级):

1. 把修复点放在**检测阶段**而非识别阶段:行首 `=` 之所以被排除,
   是因为它是低对比度的宽扁笔画,文本检测器不将其视为独立文本块。
   可尝试在送入检测器前对该行带做形态学增强,或改用更低检测阈值的
   检测器配置,让 `=` 进入检测框。
2. 单独评估「`=` 与 `-`」混淆能否由识别侧约束解决,
   但这属于识别后处理,不能替代第 1 步。
3. 若仍沿用重裁剪路线,应**逐事件按实测外露量裁切**,
   避免固定距离导致的字形不全与网格污染,并配套对照回归测试。
4. 在任一方案给出批量证据前,**不替换正式 baseline、不修改正式 CSV**。
